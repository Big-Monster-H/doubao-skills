# 功能库（底线提案）+ 创意提案机制（上限提案）

> 提案 = 功能库（保证不漏标配）+ 创意（保证有差异）。AI 必须两层都输出，禁止只列清单，禁止伪创意。

## 一、通用功能库（按项目类型挑选，每项含实现要点）

## 二、创意提案机制（强制 3~5 个，库外原创）

### 提案规则
1. 必须独立分区输出，禁止“清单已覆盖”就跳过
2. 每个创意必须绑定本项目具体场景，满足四要素：
   - 解决什么痛点（用户在哪卡住/流失/不爽）
   - 为什么适合本项目（绑定角色/业务规则）
   - 场景故事式用户路径（“用户下单后，会看到……”）
   - 成本 + 风险标注
3. **伪创意拦截**：未绑定本项目角色/场景/规则的创意打回重写。模板式创意（“加暗黑模式”“加分享”）不算

### 创意激发路径（按此系统化思考）
1. **痛点反推**：用户在哪个环节卡住/流失/不爽
2. **竞品反推**：同行都有的别做，找没人做的缝隙
3. **数据反推**：埋点要看的指标 → 反推支撑功能
4. **传播反推**：什么功能让用户自愿分享
5. **组合创新**：两个普通功能组合出新玩法

### 创意示例（供校准，禁止直接照抄）
- 服务交易类：“下单选人后 24h 未开始自动推送提醒 + 补偿券”——治放鸽子
- 内容类：“阅读完 x 分钟解锁专属总结卡片，可分享”——传播 + 留存
- 商城类：“订单完成后生成战绩海报带邀请码，双方得券”——裂变 + 复购
- 工具类：“连续使用 7 天解锁高级功能”——习惯养成

## 三、提案输出格式（统一表格）

```
| 功能/创意 | 作用 | 开发成本 | 运营价值 | 建议（1.0必须/1.0推荐/2.0后续/否） |
```

## 四、范围控制铁律

1. 提案必须绑定 **1.0 最小可上线范围**：1.0 必须（闭环必需）/ 1.0 推荐（用户可选）/ 2.0 后续
2. 用户每加一个 1.0 功能，提示“推迟上线约 X 天 + 成本影响”，把取舍代价显式化
3. 被否功能进“后续版本池”，记录不实现
4. 输出《1.0 范围界定》：含包含功能 + **明确“不在本期做”清单**
