# 前端 UI/UX 设计规范（对标大厂水准）

> AI 默认输出“能用但丑”的页面。本文件强制设计系统、三态、交互、加载与适配规范。完成页面 ≠ 交付页面。

## 1. 设计系统先行（Phase 2 骨架阶段必须定义）

在写任何业务页面之前，先定义设计系统并落地到 app.wxss（CSS 变量）：

| 维度 | 规范要求 |
|---|---|
| 色板 | 主色 1 个 + 辅助色 2~3 个 + 语义色（成功/警告/错误）+ 中性色阶（文字主/次/弱、分割线、背景），色值统一变量 |
| 字号阶梯 | 6~8 级阶梯（如 20/22/24/28/30/32/36rpx 体系），正文/标题/数字各自固定档位 |
| 间距 | 统一间距体系（8rpx 基准的倍数），禁止随意 padding |
| 圆角/阴影 | 统一档位（卡片/按钮/弹层），禁止混搭 |
| 组件一致性 | 全局 Vant 组件 + 统一覆盖样式，禁止页面内自绘混搭 |

设计系统确定后，**所有页面必须从变量取值**，禁止页面级硬编码色值字号。

## 2. 三态完整（每个列表/详情/内容页强制）

| 状态 | 要求 |
|---|---|
| 加载态 | 骨架屏（skeleton）优先，禁止纯转圈；首屏关键区必须骨架 |
| 空态 | 有图形/图标 + 人话引导文案（“还没有订单，去挑一个吧”）+ 行动按钮（如有） |
| 异常态 | 错误说明 + 重试按钮；弱网/接口失败时优先展示缓存兜底 |

## 3. 交互细节

- 按钮防重复点击：提交类按钮必须 disabled + loading
- 下拉刷新 / 上拉加载：所有列表页必备
- 表单：即时校验，错误提示贴近字段，提交前全量校验
- 反馈：操作成功 toast / 失败 toast 统一封装；破坏性操作（取消/删除/退款）必须确认弹窗
- 授权引导：订阅消息/相册等授权，先解释用途再请求；用户拒绝后要有兜底提示
- 长列表性能：虚拟化/分页/图片懒加载

## 4. 加载与性能（页面加载质量清单）

1. **分包预加载**：`preloadRule` 配置，进分包前预下载关键分包
2. **首屏并行请求**：首页多接口并行，禁止串行等待
3. **骨架屏**：首屏立即渲染骨架，数据到达再替换
4. **图片懒加载 + 云存储压缩**：列表图压缩（如 750 宽内）、懒加载
5. **配置缓存**：平台配置本地缓存（带版本/过期），云函数侧 30s 缓存
6. **列表预加载**：滚动接近底部前拉取下一页
7. **setData 最小化**：按字段更新，禁止整对象
8. **弱网兜底**：失败重试 + 缓存兜底展示，禁止白屏

## 5. 适配

- 单位一律 rpx（设计稿 750 基准）
- iPhone 安全区：底部操作栏适配 safe-area-inset-bottom
- 大字号适配：文字内容用 rpx 自适，关键操作区不因字体放大而破版
- 真机预览检查：至少检查 iPhone 小屏 / 大屏 Android 两种机型

## 6. 动效与反馈（克制原则）

- 页面切换、卡片按压、按钮反馈有细微动效（默认 Vant 内置 + 统一过渡）
- 禁止滥用动画；动画时长统一（如 200~300ms）
- 列表加载更多有 loading 提示；关键操作有成功反馈

## 7. 文案质量

- 空态/错误/引导文案必须“人话”，禁止“网络错误”四字敷衍
- 金额展示统一格式（¥ + 两位小数）
- 时间展示统一格式；状态文案与状态机一一对应
- 术语面向用户（“接单人”不是“provider”）

## 8. 页面自查（每页交付前）

- [ ] 三态是否齐全（加载/空/异常）
- [ ] 是否全部用设计系统变量
- [ ] 是否做了真机/截图自查（布局不破、无溢出）
- [ ] 交互细节（防重复点击、反馈、确认弹窗）是否到位
- [ ] 文案是否人话
- [ ] 弱网/失败场景是否兜底
