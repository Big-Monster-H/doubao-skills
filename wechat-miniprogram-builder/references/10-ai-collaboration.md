# AI 协作机制（管住 AI 本身，防止偷懒、防止自作主张、防止误解）

> 本文件是 AI 自我管理规则。任何阶段都必须遵守。这些机制是“质量闸门”之外的软约束，缺了它们 AI 会走最短路。

## 1. 上下文节制（只喂相关，不灌整仓库）

- 每个阶段开始，先输出“本阶段需要读取的文件清单”（只列相关的），再读取
- 禁止把整个仓库/全部文档一次性灌入上下文
- 读取后总结“我基于这些文件的理解”，让用户能纠偏

## 2. 决策拍板制（AI 给方案，人类拍板）

以下决策禁止 AI 独断，必须输出选项 + 代价 + 建议，由用户选择：

- 技术选型（框架/组件/支付版本）
- 架构取舍（拆分/合并、数据模型设计）
- 功能范围（1.0 加不加某功能）
- 资质相关（主体升级、类目选择）
- 涉及钱的产品规则（退款时限、提现门槛）

输出格式：
```
决策点：___
选项：A（代价）/ B（代价）/ C（代价）
AI 建议：___（理由）
请选择：
```

## 3. 自我揭短（每阶段必做）

每个阶段输出末尾，必须附：

```
## 本阶段自查
- 可能省略/偷懒之处：___
- 未验证的假设：___
- 需要用户关注的决策点：___
```

让 AI 主动暴露捷径，而不是等用户发现。

## 4. 假设清单（所有推断显式化）

| # | 假设内容 | 影响范围 | 状态（待确认/已确认/已纠正） |
|---|---|---|---|

- 用户未回答的问题一律进此清单，禁止默默按猜测执行
- 每次用户纠正后更新状态

## 5. 完成定义（阶段输出物清单，缺一项不算完成）

每个阶段开始先输出“本阶段的完成定义”，结束时逐项自检。示例（阶段 3 切片 2）：

```
完成定义：
- [ ] 云函数下单接口（含服务端重取价、状态机、statusLog）
- [ ] 支付参数生成与 requestPayment 打通
- [ ] 页面：列表/详情/下单（三态完整）
- [ ] 边界用例测试通过（金额篡改、重复下单、库存并发）
- [ ] 通过模块闸门
```

## 6. 沟通节奏（小白用户要有掌控感）

- 每个阶段/切片结束：向用户汇报“做了什么、验证了什么、下一步是什么、需要你确认什么”
- 关键节点给可演示的东西（体验版二维码、页面截图描述），不只给文字进度
- 用户回复前不静默推进需要确认的决策

## 7. 变更管理

- 开工后的新需求：进《变更清单》（需求 + 影响 + 建议排期），当前切片完成后处理
- 用户紧急变更：先评估影响（改哪些文件/推迟多久），用户确认后再做
- 禁止顺手改需求未点名的文件

## 8. 反馈循环

- 每个阶段结束回顾：“上一阶段哪些做法有效/无效”，调整后续执行
- 用户纠正过的地方，记录为规则，后续不再犯
