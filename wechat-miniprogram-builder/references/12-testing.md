# 测试策略（云函数测试 + 边界用例集）

> 目标：让“零测试”成为历史。云函数无本地环境，策略 = 抽纯函数 + mock 数据库 + 边界用例集。

## 1. 核心策略：纯函数抽取（测试可行性的前提）

业务代码中以下逻辑**必须抽成纯函数**（不依赖 wx-server-sdk / 网络），放独立文件（如 `lib/` 或 `utils/`），方可本地测试：

| 应抽取的逻辑 | 示例 |
|---|---|
| 金额计算 | 佣金、分成、券后价（输入数字输出数字） |
| 签名算法 | 支付 MD5 签名、验签 |
| 状态转换 | transition(order, from, to)（输入状态输出合法性） |
| 业务规则 | 退款时限判定、提现门槛判定 |
| 数据整理 | 列表映射、格式化 |

**禁止**：把可抽纯函数写在网络请求内联逻辑里。

## 2. 测试框架选择

- 云函数侧：Node 内置 `node:test` 或轻量 Jest（**能少依赖就少依赖**，云函数冷启动成本）
- 前端纯逻辑（utils/）：可用 Jest，若项目简单用 node:test 亦可
- 测试文件与被测代码同目录或 `tests/`，命名 `*.test.js`

## 3. Mock 方案（云函数测试）

云函数依赖 `wx-server-sdk`，测试时 mock：

```js
// mock 示例（node:test）
const cloud = {
  DYNAMIC_CURRENT_ENV: 'test',
  init: () => {},
  getWXContext: () => ({ OPENID: 'test-user' }),
  database: () => dbMock,
  openapi: { security: { msgSecCheck: async () => ({ errCode: 0 }) } }
};
```

- mock 数据库：内存对象实现 get/where/update/doc 的最小接口
- mock 场景：正常、集合不存在、超时、权限拒绝
- 被测模块通过注入依赖（函数入参传 cloud/db）或模块级 mock 引入

## 4. 边界用例集（每个涉及钱/状态的模块必测）

### 订单与支付
- [ ] 金额篡改（前端传低价）→ 服务端重取价
- [ ] 重复下单（幂等）
- [ ] 重复支付回调 → 状态只变一次
- [ ] 签名错误回调 → 拒绝
- [ ] 金额不符回调 → 拒绝
- [ ] 商户号不符回调 → 拒绝
- [ ] 订单不存在回调 → 拒绝

### 并发与原子性
- [ ] 两客户端同时抢同一单 → 仅一个成功
- [ ] 同时改状态（取消 vs 支付）→ 条件更新兜底
- [ ] 库存并发扣减（如秒杀）→ 不超卖

### 权限
- [ ] 非本人查订单 → 拒绝/空
- [ ] 非管理员调管理接口 → 403
- [ ] 越权改他人订单状态 → 拒绝

### 业务规则
- [ ] 退款时限边界（第 N-1/N/N+1 天）
- [ ] 提现门槛边界（差 1 分/刚好/超 1 分）
- [ ] 佣金率边界（0、0.15、1、>1 归一化）
- [ ] 优惠券叠加/过期/已用

### 数据层
- [ ] 集合不存在（safeGet 返回空不抛错）
- [ ] 分页边界（page=0、超上限、最后一页）
- [ ] 超长文本截断

## 5. 每切片测试完成定义

- [ ] 该切片纯函数全部有测试且通过
- [ ] 该切片涉及边界用例集全部执行
- [ ] 测试结果记录在交付说明中（跑了哪些、通过哪些）

## 6. 测试报告格式（阶段 4 输出）

```
## 测试报告
- 执行范围：___
- 用例数：__（通过/失败）
- 覆盖模块：___
- 失败项：___（必须修复后重跑）
- 未覆盖项：___（说明原因 + 风险等级）
```
