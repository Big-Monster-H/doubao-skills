# 安全与合规清单

> 安全 = 代码层清单 + 攻击自测剧本（见 05-quality-gates.md）。本文件侧重：主体决策、合规红线、隐私、内容安全。

## 1. 主体类型 → 功能边界决策树

```
主体类型？
├── 个人主体
│   ├── 可：基础功能、云开发、订阅消息、内容展示
│   ├── 不可：微信支付、电商/虚拟支付类目、手机号快速验证组件
│   └── 动作：如需收款/电商 → 明确告知需升级个体户/企业，列为最高优先级前置
├── 个体工商户
│   ├── 可：微信支付、电商类目、手机号组件
│   └── 限制：部分行业（医疗/金融/教育资质类）仍受限
└── 企业主体
    └── 全能力，需营业执照等材料
```

## 2. 类目与资质（提审前必须核对）

- 小程序类目必须与业务一致（电商/生活服务/工具等），涉及行业需对应资质（食品经营、ICP、出版物等）
- 类目不符 = 审核不通过 = 上线失败。架构阶段就要确定类目，交付文档中写明所需资质清单
- 微信认证（300 元/年）决定部分能力（如部分类目、支付相关），如实告知用户

## 3. 隐私与用户协议（提审必备）

- 用户协议 + 隐私政策页面必须存在（subpkg 独立页面），首次使用引导确认
- 隐私接口声明：收集的信息（手机号/相册/位置等）必须在隐私协议中声明，与小程序后台“用户隐私保护指引”一致
- 授权弹窗：收集前先说明用途；拒绝后给出兜底路径
- 用户可注销/删除数据：提供注销入口（合规要求，不做 = 审核风险）

## 4. 内容安全（UGC 必审）

- 用户可输入内容（昵称、评价、投诉、聊天）必须过 `msgSecCheck`
- 用户上传图片（头像、评价图、收款码）必须过 `imgSecCheck`
- 审核服务异常时：记录日志 + 降级策略（不阻断业务但标注待审），禁止静默放行恶意内容
- 敏感操作留痕：管理员操作日志（谁、何时、做了什么）

## 5. 审核红线清单（决定能不能过审，架构阶段就自查）

| 红线 | 说明 |
|---|---|
| 诱导分享 | 强制分享/分享得奖需合规设计（主动分享，不诱导） |
| 虚拟支付 iOS | iOS 虚拟商品/服务不能用微信支付，需替代方案 |
| 类目不符 | 业务与类目/资质不匹配 |
| 隐私缺失 | 无隐私政策/协议/授权声明 |
| 敏感内容 | 违禁词、违规图片、涉政涉黄涉赌 |
| 虚假宣传 | 夸大收益/虚假数据/绝对化用语 |
| 用户数据安全 | 明文存储密码/敏感信息、越权访问 |

## 6. 数据安全

- 密码/敏感字段：禁止明文存储（小程序基本无密码场景，openid 即身份）
- 密钥管理：AppSecret、支付密钥、证书只进云函数环境变量
- 日志脱敏：日志中禁止打印完整密钥、证书、支付签名参数
- 集合权限最小化（见 02-architecture.md）
- 数据库定期导出备份（见 09-delivery.md）

## 7. 提审前自查清单

- [ ] 类目与资质已核对
- [ ] 用户协议 + 隐私政策 + 注销入口已就位
- [ ] 隐私保护指引已配置（后台）
- [ ] UGC 内容安全已接入
- [ ] 无诱导分享/虚拟支付 iOS/虚假宣传问题
- [ ] 管理员操作留痕
- [ ] 密钥零前端、日志无敏感信息
