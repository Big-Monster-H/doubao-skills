# 微信小程序平台硬知识（AI 不查就翻车的约束）

> 平台规则会更新，构建时以微信官方最新文档核验数字，但以下“存在约束”这件事本身是确定的，必须遵守。

## 1. 包体积

- 主包、单个分包、总包均有体积上限（历史上主包 2MB，整体含分包约 20MB 量级）
- 策略：图片走云存储不打包；大页面/低频页进分包；公共组件/依赖进主包
- 每次构建后检查包体积，超限必须拆包，禁止硬塞

## 2. 云函数

- 事件云函数有超时上限（默认很短，可配置延长，上限以官方为准）
- 冷启动：减少顶层依赖、避免大依赖（如不需要就不用重型 npm 包）
- 环境变量：密钥/配置走环境变量，禁止写死代码
- 单函数职责单一，体积纪律见 02-architecture.md
- 定时触发器（cron）：`config.json` 配 triggers，用于超时订单退回、定时任务等

## 3. 云数据库

- 小程序端单次查询条数有限制（默认 20 条左右），云函数端上限更高（数百~1000 量级）
- **必须分页**，禁止无 limit 查询
- 客户端并发 watch 数量有限（常见上限 5 个左右）——watch 只用于真正需要实时的场景（如接单大厅），普通列表用下拉刷新/轮询
- 索引：按查询模式建索引（见 02-architecture.md），无索引的复杂查询会失败或慢
- 集合权限：敏感集合禁止客户端直读（见 02-architecture.md）

## 4. 订阅消息

- 一次性订阅：每次发送前需用户点击授权（`wx.requestSubscribeMessage`），授权一次发一次
- 长期订阅：仅特定类目可用，默认不假设
- 模板字段类型严格（thing/amount/time/character_string/phrase 等），长度有上限（如 thing 20 字、amount 需数字）
- 字段与模板不匹配 = 发送失败。云函数必须先拉模板列表解析字段再组装（或按已知模板字段硬编码）
- 发送失败要有日志兜底，不阻塞主流程

## 5. 手机号快速验证组件

- `getPhoneNumber` / 手机号快速验证需要**非个人主体**认证
- 个人主体项目不可用——架构阶段就要判定（见 07-security-compliance.md）

## 6. 云存储

- 图片/文件走云存储 + CDN，不打包进代码
- 上传时压缩（列表图控制尺寸）
- 临时链接有有效期（如 2 小时），长期展示需刷新或使用永久路径策略

## 7. 静态托管 / HTTP 云函数（管理后台）

- 管理后台页面走云开发静态托管，或 webAdmin 类 HTTP 云函数
- 访问域名格式：`https://<envId>.service.tcloudbase.com/<路径>`
- 支付回调地址需用此域名并可在商户平台配置
- 合法域名：云开发域名天然合法，无需额外配置 request 合法域名（非云开发场景才需要）

## 8. 登录与身份

- 登录：`wx.login` → code → 云函数 `cloud.getWXContext().OPENID` 获取身份，openid 永不自前端传入
- 用户资料：`wx.getUserProfile` 或头像昵称填写能力；获取前需授权引导
- 管理员身份：用 platformConfig.adminOpenids 或 users.isAdmin 在云函数内校验，禁止前端判断

## 9. 审核与发布

- 提审：体验版 → 提交审核 → 审核通过 → 发布
- 审核周期一般 1~3 个工作日，高峰期更长，交付文档中如实告知
- 审核需类目 + 资质 + 隐私材料齐备（见 07-security-compliance.md）

## 10. 其他常见坑

- `wx.requestPayment` 参数需小程序端二次签名（时间戳/随机串/包/prepay_id/签名）
- 页面栈上限 10 层，深跳转用 `redirectTo`/`reLaunch`
- 分享：`onShareAppMessage` 自定义；禁止诱导
- 定时器/监听器在 onUnload 清理，防内存泄漏
- 云函数返回数据大小有限制，大列表必须分页（再次强调）
